# Then And Now

## Proposal

适用：
- 能确认过去与现在存在真实可比关系：
  - 同一人物
  - 同一地点
  - 同一动作
  - 同一事件阶段
  - 同一物件/场景在不同时间再次出现
- 当前与历史素材都足够明确。
- 至少存在一张可执行图片。

不适用：
- 只是“看起来有点像”。
- 无法确认是同一人物或地点。
- 时间差本身没有任何可感知变化。

历史检索：
- 通常需要。
- 最多 2 次。
- 必须完整读取历史 Record 后确认真实可比，不能仅凭搜索相似度创建 Proposal。

Proposal 重点：
- 卖的是“把时间本身变成作品”。
- title 应突出“以前 / 现在”的对照感，而不是“制作今昔对比图”。
- idea 最多 2 句话：
  1. 说明会把过去和现在放在同一个视觉结构里。
  2. 说明会保留真实变化，不做虚构重现。
- plan 固定 3 项：
  - 找到过去那一刻｜确认同一人、同一地点或同一动作
  - 和今天并排｜保留真实差异和时间痕迹
  - 做成时间对照页｜用最少文字让变化自己说话
- reason 只用于内部确认“为什么这两条记录可比”。

Tag Guidance：时间重逢 + 前后变化；如“今昔重逢 / 旧地新章 / 岁月之间”。

creation 建议：
- objective：基于已授权的跨时间可比 Record 生成今昔对照视觉或时间故事。
- constraints：
  - 保留：真实人物/地点身份、时间差与环境变化
  - 转化：统一视觉语言与今昔对照版式
  - 不把相似对象当成同一对象
  - 不修改真实年龄差、环境变化或人物身份
  - 不伪造过去/现在未出现的细节
- successCriteria：
  - 两个时间点一眼可区分
  - 同一主体/地点的关联清楚
  - 变化真实、克制、有记忆感

---

## Execution

执行目标：
让用户一眼看到“时间经过了什么”，而不是简单把两张图拼在一起。

素材：
- 只使用 Proposal 已授权的过去与当前 Record。
- 先再次确认可比对象一致。
- 若主体身份不确定，停止，不自行猜测。

生成：
- 可以生成一张统一风格的对照主视觉，或分别对过去/现在做一致风格处理。
- 保留各自真实年龄、服装、环境和时间差异。
- 不为了“更像”而抹平真实变化。
- 不新增过去未出现的场景或人物。

版式：
- 优先使用双栏、上下时间对照或时间轴式 html-preview。
- 日期、年份和说明由 Markdown / html-preview 排版。
- 文案尽量短，让视觉差异成为重点。

完成后调用 project_manage(action=update)。
