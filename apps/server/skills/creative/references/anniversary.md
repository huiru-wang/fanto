# Anniversary

## Proposal

适用：
- Record 明确说明周年、纪念日、某件事满 N 年、首次经历的周年或同一日期回顾。
- 至少有一张可执行图片。
- 能确认纪念的“事件是什么”，但不要求一定是伴侣/婚姻关系。

不适用：
- 仅仅日期接近，没有明确周年语义。
- 必须猜测人物关系才能成立。

历史检索：
- 可检索事件起点、关键中间记录和当前记录。
- 最多 2 次。
- 所有历史 Record 必须确认属于同一事件脉络。

Proposal 重点：
- 卖的是“把一段时间压缩成一页纪念”，不是普通纪念日卡片。
- title 应围绕时间跨度和事件本身，例如“从第一次来到这里，到今天刚好一年”。
- idea 最多 2 句话：
  1. 说明会把起点、途中和今天放在同一页。
  2. 强调只使用真实发生过的记录，不替用户定义关系。
- plan 固定 3 项：
  - 找到起点｜确认第一次/最早的真实记录
  - 留下几个节点｜只选真正有变化或意义的瞬间
  - 做成纪念页｜把时间、照片和今天放在一起
- reason 作为内部关联依据，不在 UI 长篇展示。

Tag Guidance：时间跨度 + 纪念感；如“时光回望 / 一路至今 / 周年纪念”。

creation 建议：
- objective：基于已授权的同一事件 Record 制作周年纪念视觉或时间线。
- constraints：
  - 保留：真实日期、事件起点与已确认时间节点
  - 转化：周年主视觉与克制的时间纪念页
  - 不推断伴侣、婚姻、亲属等关系
  - 不编造中间事件
  - 日期与事件必须来自 Record
- successCriteria：
  - 时间跨度清晰
  - 起点和今天关系明确
  - 作品具有个人记忆感而非模板感

---

## Execution

执行目标：
用真实时间节点做一页克制的周年回顾。

素材：
- 只使用 Proposal 已授权 Record。
- 优先选：起点、一个关键中间节点、当前。
- 没有足够历史时，可以退化为“今天 + 起点”的双时间结构，不硬补内容。

生成：
- 主视觉可围绕“时间连接”设计，但不伪造真实合照或事件。
- 有人物时保持身份一致。
- 不在图像模型里依赖长文字、日期数字排版。

成品建议：
- 标题
- 起点
- 1–2 个真实节点
- 今天
- 一句简短收束

日期、时间线与说明使用 Markdown / html-preview。
不得将模糊关系写成恋爱、结婚、亲子等明确关系。

完成后调用 project_manage(action=update)。
