# Birthday Memory

## Proposal

适用：
- Record 明确说明生日。
- 至少存在一张可执行图片。
- 能确认生日主体；若主体不明确，不做跨历史聚合。

核心价值：
不是做一张通用“生日快乐”海报，而是利用 Fanto 已经记住的过去，把“这一岁”重新看一遍。

历史检索：
- 可检索同一明确主体最近一年具有代表性的 Record。
- 可检索上一次生日或去年同期。
- 最多 2 次。
- 只有主体能够可靠匹配时才使用历史 Record。

Proposal 重点：
- 有历史素材时，优先卖“这一岁的几个瞬间 / 去年到今年 / 一岁成长回顾”。
- 没有可靠历史素材时，再退化为生日主题视觉或当天照片故事。
- title 应围绕“这一岁”“从去年到今天”“今天的生日瞬间”等记忆感表达，避免“生成生日纪念作品”。
- idea 最多 2 句话：
  1. 先说会得到什么样的生日回顾。
  2. 再说会如何把过去真实记录和今天放在一起。
- plan 固定 3 项：
  - 找回这一岁的瞬间｜只选同一主体的真实记录
  - 做一张生日主视觉｜把今天作为这一页的中心
  - 组成一页成长回顾｜时间、照片和短句自然串起来
- reason 不展示给用户，仅用于说明为什么这些历史记录真的有关联。

Tag Guidance：一岁时间感 + 成长回忆；如“这一岁 / 成长拾光 / 岁岁留影”。

creation 建议：
- objective：基于生日当天与已授权历史 Record 生成一页生日记忆/成长回顾作品。
- constraints：
  - 保留：真实人物、日期与已记录的成长瞬间
  - 转化：生日主视觉与一页成长回顾
  - 不推断具体年龄
  - 不推断亲属关系
  - 不增加未记录成长事件
  - 只使用 Proposal 已授权 Record
- successCriteria：
  - 读起来像“这个人的这一岁”，不是通用模板
  - 时间线真实
  - 当天照片和历史瞬间有自然联系

---

## Execution

执行目标：
把“生日”从一个日期变成一段有个人记忆的时间切片。

素材：
- 只使用 Proposal recordIds 已授权 Record。
- creator-agent 不再搜索其他历史。
- 优先选当天主图 + 1–3 个最有代表性的历史瞬间。
- 历史素材不足时，不硬凑时间线。

生成：
- 主视觉优先使用生日当天人物照片。
- 可生成温暖、克制的纪念主图或插画化视觉。
- 人物身份、年龄感和真实外观保持一致。
- 不在图片中强依赖复杂数字、年龄或长文字。

内容结构：
- 标题
- 今天的主视觉
- 这一岁的 2–4 个真实瞬间
- 一句简短收束

时间、日期、短文使用 Markdown / html-preview。
不写未经记录的成长评价、性格变化或家庭关系。

完成后调用 creation_publish。
