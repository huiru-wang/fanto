# Photo Story

## Proposal

适用：
- 同一次经历中有多张图片，且存在明显的时间、动作、场景或事件变化。
- 单张图片不足以表达完整经历，但几张图片放在一起有自然顺序。
- Record 或关联 Record 能确认这些照片属于同一件事。

不适用：
- 只有一张强视觉照片，更适合 art-poster 或 postcard。
- 多张图之间没有明确关系。
- 需要大量虚构才能形成故事。

Proposal 重点：
- 卖的是“把散落的几个瞬间整理成一段看得完、记得住的小故事”。
- title 应像故事标题，而不是“制作图文故事”。
- idea 最多 2 句话：
  1. 说明会把多张真实照片组织成一段短小完整的视觉故事。
  2. 说明以真实经历为主，只增加少量视觉统一和二次创作，不补写不存在的情节。
- plan 固定 3 项：
  - 串起几个瞬间｜按真实时间或动作关系排序
  - 做一张故事主视觉｜为整段经历建立统一气质
  - 组成一页图文故事｜原图、创作图和短文自然衔接
- 只有当前 Record 不足以覆盖同一次经历时，才允许最多 2 次历史 Record 检索。
- 最终引用的历史 Record 必须完整读取并加入 proposal recordIds。

Tag Guidance：片段成章 + 一次经历；如“片段成章 / 这一日 / 旅途故事”。

creation 建议：
- objective：将授权的同一次经历整理成一页短篇图文故事。
- constraints：
  - 保留：真实人物、事件顺序、地点与照片中的关键瞬间
  - 转化：统一主视觉、短篇叙事节奏与图文组织
  - 不编造没有记录的过程、对话、地点或情绪
  - 所有照片必须属于同一次明确经历
  - 至少生成 1 张二次创作视觉
- successCriteria：
  - 有清晰开头、过程和收束
  - 原图与二次创作图风格协调
  - 阅读长度短、容易看完

---

## Execution

执行目标：
把真实照片从“几张素材”变成“一段有顺序、有重点的视觉记忆”。

素材整理：
- 先完整读取所有授权 Record。
- 仅按可确认的时间、动作、地点和场景关系排序。
- 不为填补叙事空白而编造事件。

生成：
- 至少生成 1 张二次创作图片，作为故事封面、转场或核心主视觉。
- 生成图应从真实照片提取主体与场景，不创造新的关键事件。
- 若有人物，必须保持人物身份一致。
- 不需要把每张原图都重生成。

成品结构建议：
1. 一个简短作品标题
2. 一张主视觉
3. 2–5 个真实瞬间
4. 每个瞬间 1–2 句短文
5. 一个自然收束

排版：
- 优先 Markdown / html-preview。
- 原图和生成图可以混排。
- 文字以“真实经历说明”为主，不写成小说。

完成后调用 project_manage(action=update)。
