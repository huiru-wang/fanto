# Roleplay

## Proposal

适用：
- Record 中有明确人物主体，且至少有一张可执行人物图片。
- 场景与历史、文学、动漫、影视、游戏、节庆或其他主题世界观之间存在自然关联。
- 用户能一眼理解“如果把这一刻变成某种角色/时代，会很有意思”。

不适用：
- 普通人物随手照，没有明确主题线索。
- 只有古建筑，但缺少文化或作品关联。
- 仅因为儿童、古风场景或服饰就强行套角色。

Proposal 重点：
- 卖的是“让真实的人走进一个熟悉的世界”，不是“换衣服”本身。
- title 应优先写成作品感标题，例如“在大观园里，试着走进一次红楼梦”，避免“生成红楼梦换装写真”。
- idea 最多 2 句话：
  1. 先说最终成果：一组有明确主题的角色写真/人物海报。
  2. 再说最重要的保留与转化：保留本人长相、年龄感和姿态，只改变服饰、发饰与环境氛围。
- plan 固定 3 项，围绕用户能看到的结果：
  - 保留本人｜脸部、年龄感和姿态不变
  - 进入主题｜服饰、发饰与场景统一到同一世界观
  - 做成作品｜输出统一风格的写真或图文页
- reason 只作为内部依据，指出场景与主题关联，不写成 UI 长解释。
- 默认不检索历史 Record；只有同一次主题旅行/活动明确存在其他素材时才允许检索。

Tag Guidance：文化/作品世界 + 写真作品感；如“红楼入画 / 古典写真 / 大观园”。

creation 建议：
- objective：基于授权人物原照生成主题角色写真或人物视觉作品。
- constraints 必须包含：
  - 保留：人物身份、五官、年龄感、发型基础特征和身体比例
  - 转化：已确认的服饰、发饰、配饰、场景和主题氛围
  - 不改变人物数量和关系
- successCriteria 聚焦：
  - 一眼仍能认出原人物
  - 主题世界观清晰
  - 多张图风格统一但画面不重复

---

## Execution

执行目标：
把真实人物放进已确认的主题世界，同时把“像本人”放在风格化之前。

素材：
- 优先选择人物脸部、姿态和服装信息最清晰的 1 张主图。
- 多图只有在补充同一人物身份特征或同一场景时使用。
- subjectMediaId 必须指向明确主人物原图。

生成原则：
- 保留：人物数量、身份、年龄感、五官、脸型、发型基础特征、表情倾向、身体比例和自然姿态。
- 转化：服饰、发饰、配饰、布景、时代/作品氛围、光线和画面语言。
- 不把真实人物改成卡通脸、成人化儿童、不同年龄或陌生人。
- 不机械复制影视剧照；应保留真实照片中的人物关系和构图依据。
- 每张图应有明确差异，可改变景别、环境重点或主题细节，但不能改变人物身份。

Prompt 应明确包含：
- 原图必须保留的身份和姿态信息
- 已确认主题
- 允许变化范围
- 禁止变化项
- 场景氛围和视觉语言

发布：
- 生成图全部使用稳定 fanto-media:// mediaId。
- Project 内容可用 Markdown / html-preview 组织成一组主题写真。
- 文案只描述真实拍摄背景与“基于原图的二次创作”，不把角色扮演写成真实发生。
- 完成后调用 project_manage(action=update)。
