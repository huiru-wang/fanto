### T2 建立 context 模块与纯函数组装

依赖：T1。

- [ ] 建立 types、prepare-context、compose-prompt、context-budget 与集中策略配置。

- [ ] 在 SessionManager 共用执行入口接入准备流程；动态回调仅做同步组装。
- [ ] 在 harness 层提供受限近期对话视图，不让 context 依赖 Pi entry 格式。
- [ ] 接入执行保护、AbortSignal、独立分支降级和总 deadline。
- [ ] 验证稳定顺序、转义、分区预算、不同 run 隔离、空数据兼容、历史不累积。

验收：正常请求和压缩用途边界明确；不修改共享 definition；无网络 I/O 藏在组装回调内。

### T3 整理 Core 与默认 natural Profile

验收：默认人格保留，工具权限不变；不建设角色选择、首次问候或用户角色设置。

## 阶段三：自动记忆召回

### T6 搜索结果透传事件时间

依赖：实施前复核现有 Memory 工作区改动。

- [ ] 检查现有 Document、IndexHit、索引 metadata 的 eventAt 支持，不重复改造。
- [ ] 透传至 SearchResult、HTTP、Agent schema 与 record_search。
- [ ] 验证文本、图片、音频命中保留时间及原子来源，用户隔离不回归。
- [ ] 如涉及索引变更，在独立环境验证 rebuild，不重建用户业务数据。

验收：自动召回与普通搜索使用同一完整结果契约，无逐条读取时间的 N+1 请求。

### T7 Planner 与确定性检索编排

依赖：T2、T6。

- [ ] 配置独立快速模型与适配器；输入近期对话及当前消息，输出 0～2 条查询。
- [ ] 校验结构、查询数量与长度；无效或超时降级，不做关键词 Search Gate。
- [ ] 并行搜索，按原子身份去重、相关度过滤、稳定排序与完整条目限量。
- [ ] 初始每 query topK=8、注入最多 3 条，阈值与长度预算集中配置。
- [ ] 保留成功查询结果，正确处理总超时和用户取消，不引入召回后模型摘要。
- [ ] 更新有效记忆与真实媒体 ID 来源规则，回归 Record Tool 和 present_media。

验收：准备失败不阻断普通聊天；取消不继续生成；证据只用于本轮，不写偏好或历史。
