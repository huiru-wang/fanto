# H5 客户端

React / Vite 受控测试客户端，提供 Records、默认 Main、多角色对话与角色管理。未知地址回到 Records。没有正式公开登录，使用构建时测试 refresh token 换取 JWT，配置不提交到 Git。

## 角色管理

`/fantos` 显示默认 Main、活跃角色、归档角色与待确认删除清理。支持创建、选择、归档、恢复和物理删除；同时最多 3 active，归档不占名额。可从聊天顶部切换角色或进入管理，也可从设置进入角色与对话。

`/fantos/new` 创建角色，nickname、description 和四段 roleConfig 都可留空；创建时提示身份将固定。成功后自动选择该角色的固定 Session 进入聊天。创建响应不确定时保留草稿并禁止直接重复创建，应先回列表核对，避免非幂等 POST 重复创建。

`/fantos/:fantoId` 只读显示身份，允许调整独立 agentConfig 和头像。三个开关分别控制 User Record 读取、User Memory 仅读、动作旁白；角色独立记忆始终启用。配置只 PATCH 变化子键，版本冲突先读远端，合并独立字段、保留本地修改，用户核对后再次保存，不自动覆盖。头像沿用裁切/上传/complete 及独立版本化绑定流程。归档角色仅查看设定，需恢复后再修改。

删除需明确确认；用户个人记录和其他角色保留。202 表示角色已删除但媒体清理未完成，保留同用户的显式重试目标；待清理目标按用户存 sessionStorage，刷新后可恢复。响应丢失时先查询角色是否仍存在，再决定让用户重新确认删除还是重试清理。没有自动重试或虚报完成。

## 固定会话与状态隔离

默认 Main 通过 GET /api/agent/main-session 幂等获取；角色 sessionId 来自角色响应，H5 不创建或重绑定 Session。旧 /fanto/settings 页面重定向到当前角色或列表；旧设置 API 已不再调用。

选中角色按用户存 sessionStorage，失效/归档/删除回退默认 Main。ChatPage 以服务端 Session ID 为 React key，切换时分离旧 SSE、恢复和分页回调，确保不同角色不会混入消息。草稿按 Session 存 sessionStorage；默认 Main 和不同角色的草稿独立。站内切页继续保留当前聊天组件，刷新后从固定 Session 历史恢复。

首次、网络异常及重新激活时核对 History 的 running/stopping；恢复不重放 POST。切换角色会分离前端输出，不取消服务端正在运行的对话；切回通过 History 恢复。归档/删除/修改配置遇到 FANTO_BUSY 提示当前回复结束后重试。历史按完整 Run 分页，主会话 sessionId 可复制供受控调试。

Markdown、媒体与 Tool 活动继续复用主对话组件，不展示原始工具 JSON 或凭据。SSE 停止/恢复契约见 Agent Runtime。

## 记录与媒体

支持文字/图片/音频记录、录音、时间线和搜索。保存失败保留草稿与上传阶段，仅用户再次提交才重试。小图使用 thumbnail，原图使用 original，缓存按 mediaId/variant 区分；音频读取原始媒体。详见 Media。

## 测试用户与验证

服务端显式命令 `pnpm --filter @fanto/server db:seed:test-user` 插入 active 的 user001，已存在时不覆盖状态或时间。不在迁移、启动时自动种测试用户，也不创建登录身份或提交测试凭据。

构建检查：pnpm --filter @fanto/h5 typecheck / test / build。状态测试覆盖角色级版本比较、失效回退、配置合并和 PATCH 范围；浏览器验收覆盖创建 3 个角色（含空身份）、切换/草稿隔离、固定 Session、版本冲突、归档恢复、删除和窄屏布局。真实模型与对象存储仍需单独配置 smoke，不将模拟流式响应当作真实模型验收。
