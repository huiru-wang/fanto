# H5 客户端

React / Vite 受控测试客户端，仅提供系统默认 Fanto、多角色对话与角色管理。默认与未知地址均进入 `/chat`，旧 `/records`、`/settings` 地址也回到对话。无侧栏和底部导航。没有正式公开登录，使用构建时测试 refresh token 换取 JWT，配置不提交到 Git。

## 角色管理

`/fantos` 显示不可删除的系统默认 fanto、活跃角色、归档角色与待确认删除清理。支持创建、选择、归档、恢复和物理删除；同时最多 3 active，归档不占名额。聊天页仅包含消息主体、输入框、左上角当前头像与 nickname 胶囊、右上角角色头像组和重新开始对话图标（头像组最多展示两个 active 角色，当前角色优先，多余角色以 +N 角标显示）。点击左侧进入当前角色详情，右侧进入角色选择页；选择页通过头像卡片切换角色，右上角加号创建角色，满额时禁用。胶囊、输入框与角色卡采用浅色半透明玻璃样式，支持移动端安全区域。

`/fantos/new` 创建角色，nickname 必填、不可占用 fanto，且在当前用户下不可与活跃或归档角色重名（不区分大小写）；仅填写头像、角色名称与四段 roleConfig（角色设定、世界与关系、交流方式与边界、示例对话），设定可留空；不展示简介或对话能力。H5 创建请求显式开启 `fantoMemoryEnabled` 与 `narrationEnabled`，`recordReadEnabled=false`；不改变既有角色或系统默认角色配置。创建时提示身份将固定。成功后自动选择该角色的固定 Session 进入聊天。创建响应不确定时保留草稿并禁止直接重复创建，应先回列表核对，避免非幂等 POST 重复创建。

`/fantos/:fantoId` 头像居中置顶，下面按顺序只读显示角色名称及四段角色设定；不提供对话能力开关或配置保存。头像沿用裁切/上传/complete 及独立版本化绑定流程，角色设置仍遵守服务端身份固定规则。归档角色仅查看，需恢复后再修改头像。

删除需明确确认；用户个人记录和其他角色保留。202 表示角色已删除但媒体清理未完成，保留同用户的显式重试目标；待清理目标按用户存 sessionStorage，刷新后可恢复。响应丢失时先查询角色是否仍存在，再决定让用户重新确认删除还是重试清理。没有自动重试或虚报完成。

## 固定会话与状态隔离

默认 fanto 通过 GET /api/agent/main-session 幂等返回 `{sessionId,agentId,scopeKey}`，其中 `scopeKey` 必须和角色列表中的默认 `fantoId` 一致、`sessionId` 也必须一致。所有角色均使用真实 FantoId，角色 sessionId 来自角色响应，H5 不创建或重绑定 Session。旧 /fanto/settings 页面重定向到当前角色或列表；旧设置 API 已不再调用。

选中角色按用户存真实 FantoId 到 sessionStorage，旧值 `default`、失效/归档/删除的选项都解析成默认 fantoId，不再存字符串 `default`。验证默认角色数据与 Session 对应后才能开始对话，不可在角色缺失时退回无绑定 Session。ChatPage 以服务端 Session ID 为 React key，切换时分离旧 SSE、恢复和分页回调，确保不同角色不会混入消息。草稿按 Session 存 sessionStorage；默认 fanto 和不同角色的草稿独立。站内切页继续保留当前聊天组件，刷新后从固定 Session 历史恢复。

首次、网络异常及重新激活时核对 History 的 running/stopping；恢复不重放 POST。切换角色会分离前端输出，不取消服务端正在运行的对话；切回通过 History 恢复。归档/删除/修改配置遇到 FANTO_BUSY 提示当前回复结束后重试。历史每次请求 `limit=10`，按完整 Run 分页（不是严格 10 条消息）；用户向上滚动至顶部 16px 范围时补载更早一批，补载后保留滚动位置，不因程序滚动到底部而预加载；聊天页不再展示 Session 调试信息。

Markdown、媒体与 Tool 活动继续复用主对话组件，不展示原始工具 JSON 或凭据。SSE 停止/恢复契约见 Agent Runtime。

## 重新开始对话

右上角编辑图标通过确认弹窗重新开始当前角色的对话：永久删除旧 Session 的消息与用量、该角色长期记忆，创建并绑定新 Session，角色设定和头像保留。系统默认 fanto 同样支持。运行/恢复期间禁用，服务端并发运行返回 FANTO_BUSY；新 Session ID 自动重建聊天组件并清除旧草稿。请求结果不确定时只 GET 核对绑定，不自动重发破坏性 POST。

## 动作与旁白输入

输入框外侧上方的「动作与旁白」按钮在光标处添加独立描述区（可反复添加），用户不需要输入 Markdown 符号。描述区按回车结束并聚焦语言区，中文输入法选字不触发结束或发送；语言区 Enter 发送，Shift+Enter 换行，移动端也可点发送。描述区与语言区可编辑，空区按退格移除。

发送时按顺序转换为普通段落与 `> ` 引用块，每行旁白都带引用前缀，块间空一行；空描述不发送。用户消息和角色回复共用 Markdown 渲染及段落、引用块样式；描述区不展示额外提示标签。草稿以带类型的分段结构按固定 Session 保存，兼容读取原纯文本草稿；消息接口和持久化仍使用原有字符串。

## 媒体

H5 不再提供记录的创建、时间线、搜索和设置页面；服务端与 iOS 记录能力保留。对话内媒体展示和角色头像上传仍使用共享媒体链路。

## 测试用户与验证

服务端显式命令 `pnpm --filter @fanto/server db:seed:test-user` 插入 active 的 user001，已存在时不覆盖状态或时间。不在迁移、启动时自动种测试用户，也不创建登录身份或提交测试凭据。

构建检查：pnpm --filter @fanto/h5 typecheck / test / build。状态测试覆盖角色级版本比较、真实默认 FantoId 回退、昵称唯一校验、配置合并和 PATCH 范围；浏览器验收覆盖默认 fanto 加 2 个自定义角色（昵称必填）、切换/草稿隔离、固定 Session、版本冲突、归档恢复、删除和窄屏布局。真实模型与对象存储仍需单独配置 smoke，不将模拟流式响应当作真实模型验收。
