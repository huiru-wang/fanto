# H5 客户端

入口：`apps/h5`，React + TypeScript + Vite。

## Project / Proposal（异步执行 V3）

- Proposal 接受：`POST /api/proposals/:id/accept` 只返回 `result.projectId`，直接打开 Project；不再调用 Session/start。
- 非归档 Project 列表默认查询 `GET /api/projects`，包括 queued/running/completed/failed；传 `status=archived` 查看归档。
- `Project.status` **仅反映任务执行状态**：queued 等待处理、running 正在执行、completed 成功、failed 本轮失败、archived 只读。`sessionId` 是独立的会话引用，允许 queued/running 下为空或非空；旧作品内容和封面不因状态改变而隐藏。
- 只有 completed/failed 可发起新的 Project 对话与归档；存在 Session 时，其历史在任何 Project 状态下均可读取。
- `GET /api/agent/sessions/:sessionId/history` 读取通用会话历史；`GET /api/agent/sessions/:sessionId/events` 用携带 JWT 的 `fetch` 订阅实时 SSE；继续创作通过 `POST /api/agent/stream` 使用 `creator-agent` 和已绑定 sessionId 直接消费 SSE。
- 只读 SSE 订阅失败不阻止 completed/failed Project 继续发送消息。请求驱动的 `/api/agent/stream` 与 Main Chat 共用消息块渲染（Markdown、媒体、Tool Presentation），按 toolCallId 展示活动的开始/完成，不直接向用户呈现原始工具 JSON 或技术 ID。SSE 断线后读取 History 并重建订阅，不自动重发 POST；`done/error` 后同步历史与 Project 内容。
- 列表存在 queued/running 时低频刷新可见项目；详情仅在 queued/running 时低频 GET 状态，不能只比较 `version`，因为状态/Session 绑定不增加内容版本。
- TaskRun 新增 queued，展示等待执行，与 running 区分；Task 本身 active 等状态不变。
